# design-sync notes — Campfire

Repo-specific gotchas for `/design-sync`. Read this before a re-sync.

## This repo is outside the converter's normal envelope

Campfire has **no design-system package**: the UI lives in `apps/web`, a private
Vite app with no `dist/` library entry, no barrel, and `noEmit: true` in
`tsconfig.json` (so there is no `.d.ts` tree for the converter to discover
components from). Three things bridge that gap, all generated by
`node .design-sync/gen-entry.mjs`:

- `apps/web/.ds-entry.tsx` — the entry barrel (gitignored, regenerate freely).
  It **must** live under `apps/web`: `package-build.mjs` derives `PKG_DIR` by
  walking up from `--entry` to the `package.json` whose name matches `cfg.pkg`.
  `--entry` itself resolves against **cwd**, not the package dir.
- `.design-sync/groups/<Name>.md` — frontmatter-only category stubs, bound via
  `cfg.docsDir`. A stub whose body is empty is falsy in `emit.mjs`, so the
  `.prompt.md` is still fully synthesized from props + JSDoc; only the
  `category:` is taken. This is how 116 components get 14 real groups instead
  of all landing in `general`.
- `cfg.componentSrcMap` — the authoritative component list. Because there are no
  `.d.ts` exports, `names` starts empty and the map alone defines what becomes a
  card. Anything in the barrel but not in the map ships in the bundle without
  becoming a card (that is how `DsPreviewSurface` and `RollResultToastProvider`
  are handled).

Re-run `gen-entry.mjs` after adding/renaming a component; it rewrites the barrel,
the stubs, and `componentSrcMap` in place while preserving all other config keys.

## Build

`cfg.buildCmd` is the whole prerequisite chain. Notes on each link:

- **`npm ci` fails** — `better-sqlite3@11.10.0` cannot compile its native addon
  under Node 26 (`node-gyp` → `make` exit 2), and npm rolls the whole install
  back, leaving `node_modules` empty. Use **`npm ci --ignore-scripts`**. That is
  the server's dependency; nothing in the web toolchain needs it. esbuild and
  rollup still work afterwards (they ship prebuilt platform binaries as optional
  deps, not postinstall downloads).
- **Build `packages/schema` first.** `apps/web` imports `@campfire/schema`, and a
  worktree otherwise resolves the parent checkout's stale build.
- **`--node-modules` is the repo ROOT `node_modules`.** npm workspaces hoists
  `react`/`react-dom` there; `apps/web/node_modules` is sparse.

## CSS: Tailwind v4 means the stylesheet only exists after a build

`cfg.cssEntry` points at `dist/campfire-ds.css`, which the build step derives
from Vite's content-hashed `dist/assets/index-*.css` (the hash changes every
build, so it cannot be referenced directly).

The `sed` in `buildCmd` is **not cosmetic**. Vite emits font URLs as
`url(/assets/…)`, and `lib/css.mjs` resolves them with
`resolve(srcDir, u)` — a leading `/` makes that absolute, so every one of the 88
`@font-face` rules resolved outside the build and was silently dropped
(`fonts/` contained only `fonts.css`, and Inter/Fraunces never shipped). Rewriting
`url(/assets/` → `url(./assets/` makes all 88 resolve and copy. If a future
sync reports `[FONT_DANGLING]` or an almost-empty `fonts/`, check this first.

## Campfire is dark-only; the card chrome is not

Generated preview cards hard-code `<style>body{…background:#fff}</style>` *after*
the stylesheet link, so Campfire's light-on-dark components rendered against
white. Fixed with `cfg.provider` → `DsPreviewSurface`
(`.design-sync/preview-surface.tsx`), which re-establishes the real surface
inside `#root` using only the DS's own tokens (`--color-bg`, `--color-text`,
`--font-body`).

That wrapper deliberately has **no `padding` and no `minHeight`**. The card's
floor-card fallback fires on a zero-height root; giving the wrapper its own box
suppressed the honest "preview not yet authored" card for every unauthored
component and replaced it with an empty dark box (floor cards dropped 60 → 44).
Do not add spacing there — authored previews supply their own.

## Scope

`components/**` in full, plus a curated slice of `features/**` (presentational,
reusable pieces only — route components, admin data cards, and wizards are app
screens, not design system). The allowlist is `FEATURE_ALLOW` in `gen-entry.mjs`.
`RollResultToastProvider` and the `*Provider`/context exports are excluded from
the card list by `NOT_A_CARD` / `BUNDLE_ONLY`.

## Known render warns

13 components render an empty card by nature, not by defect. They are fully
importable and their `.d.ts` / `.prompt.md` are correct — only the static
screenshot is blank. Do not re-chase these without new information:

- **Server-gated** (render nothing until an API responds; the preview harness
  has no server): `AiModeBadge`, `CatchUpPanel`, `SafetyHoldBar`,
  `SafetyHoldDisplayOverlay`, `GetAMapPanel`, `DraftWithAiButton`,
  `QuickCaptureDialog`.
- **Environment-gated** (only mount under a real PWA install/update event):
  `InstallHintBanner`, `PwaUpdateBanner`.
- **Need live composite props**: `CharacterCompletionBanner` (a full
  `RuleSystemAdapter`), `DmLifecycleHeader` (~20 coupled props + handlers),
  `GridOverlay` (calibrated map geometry in surface pixels).
- **Genuinely tiny**: `RequiredMarker` is a single inline `*` glyph.

`FloatingNumbers` and `DiceRollOverlay` are animation overlays — their captures
are honest mid-animation frames and will differ run to run.

## Authored previews

16 components have hand-authored previews under `.design-sync/previews/`, all
graded good. Three API facts cost a debugging cycle each and are worth keeping:

- `RolledDice`'s `kept` is the subset of kept **values** (multiset-matched
  against `rolls`), NOT indices — passing indices strikes every die through.
- `StatBlock`'s `abilityScores` keys must be long-form (`strength`, `dexterity`,
  …); `STR`/`DEX` are silently ignored and the ability row vanishes.
- `FloatingNumbers` events are `{combatantId, kind, amount?}` — there is no
  `delta` field, and passing one renders the literal text "undefined".

## Re-sync risks

- **`gen-entry.mjs` group map rots.** `GROUPS` in that file is a hand-maintained
  name→category map. A renamed or new component silently falls through to
  `Components`; the script prints `ungrouped -> Components: …` — watch for it.
- **`FEATURE_ALLOW` names are matched by export name.** If a feature component is
  renamed, the script prints `! <feature>: not found <Name>` rather than failing.
- **The font `sed` is coupled to Vite's output convention.** If the web build
  ever emits a different asset path prefix, the rewrite silently stops matching
  and fonts vanish again. Verify `ls ds-bundle/fonts | wc -l` is ~89, not 1.
- **`cfg.cssEntry` depends on the app build succeeding.** It is the full compiled
  app CSS (~162 KB), so it carries Tailwind utilities actually used by app
  source. A component whose classes only appear in unscanned code would render
  unstyled.
- **Node 26 + `better-sqlite3`** will keep breaking a plain `npm ci` until that
  dependency is upgraded.
